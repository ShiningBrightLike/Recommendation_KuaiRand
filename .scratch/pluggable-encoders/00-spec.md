## 问题陈述

当前的 MMoE 框架表征能力受限：共享 Embedding 与数值特征拼接之后直接进入专家层，中间没有任何特征变换模块，因此无法评估 DCN、SENet 这类推荐系统算法对特征表征的增益（架构审查 §5 已把「表征能力受限：单一共享 Embedding、无特征交叉」列为已知问题）。想要尝试一种新的特征变换算法，就必须改动模型主干，实验之间无法保持同一协议，也无法回答「哪种特征编码对四个任务更有价值」这个问题。

## 解决方案

把排序模型拆成两条可独立替换的轴：

- **特征编码器**：对拼接后的特征向量做进一步表征变换，v1 提供 mlp（默认）、dcn、senet；
- **多任务结构**：决定任务之间如何共享与分化并给出各任务输出，现有 mmoe、shared_bottom、single_task。

两者凭名称注册与选择，训练入口用 `--encoder` / `--mtl` 切换，对照脚本用「结构+编码器」组合串一次比较多个配置；每个 run 的记录里写明两轴名称与生效超参，任何落盘的模型都能通过统一加载路径复现预测。新增算法只需增加一个模块并注册，不改训练主干。

## 用户故事

1. 作为离线研究者，我想在同一份数据与同一套训练协议下切换特征编码器，以便判断 DCN 或 SENet 是否比单层 MLP 更值得引入。
2. 作为离线研究者，我想默认配置本身就带一层特征编码器，以便不额外传参就得到一个更强的基线表征。
3. 作为离线研究者，我想用名称而不是改代码来选择特征编码器与多任务结构，以便一次实验只改变一个变量。
4. 作为离线研究者，我想把两轴自由组合（例如 MMoE + DCN），以便回答「特征交叉 + 多门专家」是否叠加增益。
5. 作为离线研究者，我想在对照脚本里一次跑多个「结构+编码器」组合并用同一张表展示，以便横向比较。
6. 作为离线研究者，我想看到每种配置的参数量，以便判断增益是否只是参数膨胀带来的。
7. 作为离线研究者，我想在每个 run 的记录里看到两轴名称与生效超参，以便事后复现与审计。
8. 作为离线研究者，我想用一条命令复现别人跑出的配置，以便结论可验证。
9. 作为维护者，我想新增一个特征编码器只需要加一个模块并注册，以便扩展算法库时不改动训练主干。
10. 作为维护者，我想每个编码器自带默认超参，以便新增算法不污染全局配置。
11. 作为离线研究者，我想 SENet 按特征域而不是逐维重加权，以便它的重加权语义与推荐实践一致。
12. 作为离线研究者，我想 DCN 使用低秩交叉以控制参数量，以便在单机 CPU 上仍能完成对照实验。
13. 作为离线研究者，我想逻辑回归对照保持「无隐藏表征」的定义不变，以便它继续充当可靠的下界基线。
14. 作为离线研究者，我想单任务结构下每个任务使用各自独立的特征编码器，以便它保持「完全独立」的对照语义。
15. 作为维护者，我想保存下来的模型仍能被特征重要度流程加载，以便置换重要度可以直接作用在带新编码器的模型上。
16. 作为维护者，我想两轴分层与默认模型的变化被记录在 ADR 与术语表里，以便后来者理解为什么默认模型带了编码器。
17. 作为离线研究者，我想知道哪些历史数字已经作废，以便不误用旧结论。
18. 作为未来的 agent，我想 PLE-CGC 能作为多任务结构轴的新选项接入，以便多任务结构的对比矩阵继续扩展。

## 实现决策

- **两轴分层**（ADR-0005）：特征编码器与多任务结构各自有统一契约与注册表，两轴独立组合。
- **模块契约**：每个特征编码器都是自定义层，输入为拼接后的稠密特征向量、输出为固定维度的稠密表示，并声明自己的输出维度；每个自定义层实现配置序列化与构建逻辑，统一由注册表提供加载入口（特征重要度模块不再手写单个层的映射）。
- **v1 编码器规格**：
  - mlp：单层全连接（默认 64 维、ReLU），不加 dropout / BatchNorm；实现支持隐藏层列表但默认单层，方便后续加层而不改接口与名称。
  - dcn：DCN-v2 形态，低秩矩阵交叉 2 层（默认秩 64）与一层深度分支并联，输出保留自然维度、不额外加投影层。
  - senet：按特征域做 squeeze-excite 重加权；域划分由实际特征 schema 动态推导——每个类别特征按 embedding 维度成域，每个数值特征各成一域，随影子特征等的加入而变化。
- **多任务结构契约**：接收编码器输出，输出命名为 output_1..N 的各任务概率，保持与今日一致的输出契约与损失权重口径。
- **默认值归属**：各编码器模块自带默认超参（层数、秩、隐藏维度等），全局配置只保留两轴的选择项。
- **命令行**：训练入口新增 `--encoder`（默认 mlp）与 `--mtl`（默认 mmoe，v1 开放单模型多输出的结构）；对照脚本用「结构+编码器」组合串选择，逻辑回归不接受编码器后缀，显式组合时报错而非静默忽略。
- **可追溯性**：run 目录名默认体现两轴组合；每个 run 的指标产物记录两轴名称、生效超参与参数量。
- **产物契约不变**：输出命名、模型文件、训练曲线、训练日志与今日一致。
- **删除旧入口**：根目录的旧模型模块由 models 包取代，四处引用一并更新。
- **对照纪律不变**：不做匹配参数量的对照；结论仍要求同一协议与非单次结果（沿用既有 roadmap 纪律）。
- **文档**：新增 ADR-0005，术语表增补「特征编码器」「多任务结构」「专家混合门」（后者用于隔离 MMoE 的混合门与特征筛选的「门控」）。

## 测试决策

- **好测试的标准**：只断言对外行为——模型能按给定 schema 构建并前向、输出个数/命名/形状/概率取值范围正确、保存后能在新进程加载并复现预测、参数量只在有对照意义处断言（例如逻辑回归必须保持原有的参数量）。不断言内部层结构或张量名，避免把重构细节钉死。
- **测试接缝（一个）**：模型构建的公共入口。这是既有接缝，现有模型构建器测试已经在这里断言随机输入下的输出形状与概率范围，本次只需在同一接缝上补齐「(编码器 × 结构) 组合」与「保存 → 加载 → 预测一致」两类断言，不新增测试接缝。
- **测试的模块**：模型构建公共入口（含各编码器与各结构的组合）；训练辅助逻辑沿用现有测试。
- **先例**：现有模型构建器测试（随机输入 `predict` + 形状/参数量断言）与训练辅助测试（回调级断言）。
- **命令行之外的验证**：训练入口与对照脚本的冒烟运行保持人工执行，不升格为自动化接缝。
- **回归底线**：既有 19 条测试在整个过程中保持全绿（除导入路径外不改断言）。

## 不在范围内

- PLE-CGC 等多任务结构轴的新算法：它需要单独一轮设计拷问（分层专家、任务共享与独享、门控结构），本 spec 只保证接口留好位置。
- 分域/字段感知 Embedding、序列特征与 DIN。
- FM、PNN 等其它特征编码器。
- 匹配参数量的对照实验与超参搜索。
- CI 流水线、批量打分脚本与任何线上/生产链路形态。

## 补充说明

- **默认模型改变会作废既有数字**：README 的对照表、特征重要度产物与特征门控判定都基于旧默认模型（已记入 ADR-0005）。本 spec 的收尾工作（T6、T7）负责用新默认重跑并重新发布；在重跑之前，旧判定不得作为特征采纳依据。
- **术语冲突**：MMoE 的 gate 固定称「专家混合门」，不要复用「门控」（后者在本项目专指特征筛选的门控流程与门控指标）。
- **训练时间量级参考**（同 seed、全量数据）：逻辑回归约 80 秒、共享底层约 120 秒、单任务约 190 秒，因此多 seed 重刷是可行的。
- **交付顺序**：先预重构（T1）→ 产物可重载（T2）→ 两轴与默认编码器（T3）→ 两个新编码器（T4、T5，可并行）→ 重刷对照表（T6）与重跑置换重要度（T7）。
