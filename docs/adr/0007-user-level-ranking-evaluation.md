# 用户级曝光内排序评估

**状态：已接受**

## Context

当前模型比较主要报告逐样本 AUC。KuaiRand 是公开曝光日志，数据中有每行的 `user_id`、`video_id`、日期、行为标签，但没有线上全量候选池或可复现的召回阶段。因此可以在现有数据上做用户级离线排序评估，但不能把它解释为全量推荐 Recall 或线上排序效果。

## Decision

- 候选集合定义为某个数据划分（split）内该用户的全部曝光样本；评估名称统一为“用户级曝光内排序评估”。
- 分组键固定为 `user_id`。预处理额外保存与 X/y 行序一致的评估侧表（sidecar）：`row_id`、`user_id`、`video_id`、原始 `date`；侧表不进入模型输入。
- 点击、点赞是主任务，报告 GAUC、NDCG@10、Recall@10、MAP@10；关注、评论同样计算但只作为参考任务。
- GAUC 使用有正有负用户的 ROC AUC，并按用户曝光数加权；没有正样本或没有负样本的用户不进入 GAUC，并报告有效用户数。
- NDCG@10 与 MAP@10 对全部用户取宏平均，无正样本用户记为 0；Recall@10 只对有正样本用户平均，同时报告分母用户数。
- 分数相同时使用稳定排序，并以 `row_id` 升序作为次级排序键；`K` 通过接口传入，默认 10。
- ECE 使用固定宽度概率分箱；不把校准指标混入排序主结论。ECE 点估计按所有曝光行计算，但其百分位置信区间以用户为 bootstrap 重采样单位：每次重采样用户后，合并该批次用户的分箱计数、置信度和标签统计，再重新计算 ECE。
- 置信区间以用户为 bootstrap 重采样单位，默认 1,000 次、95% 百分位区间，并记录 bootstrap 随机种子。
- 验证集用于模型比较；最终确认集只有在模型配置锁定后，对一个配置、一个随机种子评估一次。

## Consequences

该协议不需要外部数据，能从现有公开日志生成用户级排序指标和分组置信区间；但指标只回答“给定曝光集合内能否把正反馈样本排在前面”，不能回答全量视频召回、候选生成覆盖率或线上 CTR。所有报告必须同时注明 split、候选集合、K、有效用户数和 bootstrap 口径。
