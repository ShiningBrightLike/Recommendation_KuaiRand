# 11 扩展方法地图

这一页把“已经实现”“可以规划”“明确不属于当前项目”分开，避免学习者把论文方法名误认为仓库能力。

| 方向 | 当前状态 | 它解决什么问题 | 接入前需要补什么 |
| --- | --- | --- | --- |
| MLP / DCN / SENet | 已实现 | 改变共享特征表示 | 同协议多 seed 对照 |
| Shared-Bottom / MMoE / PLE-CGC | 已实现 | 改变任务共享与分化 | 固定 split、loss 和早停 |
| 用户级曝光内排序 | 已实现 | 衡量给定曝光集合内的重排 | 不能解释为全库召回 |
| 置换重要度 | 已实现 | 衡量固定模型的输入依赖 | 同模型、同决策集、shadow 参考 |
| 严格 point-in-time 特征 | 待实现 | 消除全期统计带来的未来信息风险 | 按窗口重算、同 seed 重训 |
| DIN / 序列建模 | 未实现 | 建模用户近期行为序列 | 序列样本定义、时间边界和新评估 |
| 负采样 / 候选采样 | 未实现 | 改变训练候选分布或处理大规模候选 | 采样比例、曝光偏差和敏感性分析 |
| focal loss / 任务独立阈值 | 未实现 | 处理稀疏任务和不平衡 | 保持任务比较协议不变 |
| Platt / isotonic calibration | 未实现 | 改善概率校准 | 独立校准集，不能用 test 调参 |
| 召回与线上服务 | 明确非目标 | 评估全库覆盖、延迟和线上收益 | 新系统边界，不是本教程的小改动 |

## 推荐的扩展顺序

1. 先完成严格 point-in-time 重算，因为它会影响所有后续结论；
2. 再做序列特征或 DIN，并重新定义样本可用历史；
3. 再做采样、focal loss 或校准，明确它们改变的是训练目标还是输出解释；
4. 最后再讨论召回、服务和线上实验，不把离线精排仓库直接扩张成线上系统。

每个扩展都应新增一个实验台账条目，并在候选选择前重新确认决策集和 test 纪律。
