# FAQ

## 1. 这是一个完整的推荐系统吗？

不是。它是给定曝光集合后的离线多目标精排研究项目。召回、粗排、全量候选生成和线上服务不在实现范围内。

## 2. 0 标签是不是人工构造的负样本？

不是。它表示曝光日志中没有发生对应反馈。当前代码没有额外负采样。

## 3. 为什么训练看 AUC，排序评估还要看 GAUC 和 NDCG？

AUC 观察逐样本正负区分，用户级排序指标观察同一用户曝光集合中的相对顺序。它们回答不同问题，不能互相替代。

## 4. Recall@10 是全站召回率吗？

不是。分母是当前用户曝光集合中的正样本，候选集合不是全量视频库。

## 5. 为什么 sidecar 不直接作为模型输入？

user_id、video_id 和 row_id 容易让模型记忆标识符；它们在当前协议中只用于分组、稳定排序和审计。

## 6. 时间切分后还会泄漏吗？

会。若统计特征使用了未来窗口，按日志行切分仍然不够。必须审计每列的观测时间和聚合窗口。

## 7. 为什么不把 test 指标放进模型排行榜？

因为 test 是最终确认集。若它参与选型或调参，最终确认就被消耗了。

## 8. PLE-CGC 一定比 MMoE 好吗？

不一定。当前单层 PLE-CGC 与 MMoE+SENet 的结论只覆盖同一验证协议和三个 seed，不能外推到更深 PLE。

## 9. 置换重要度最高的特征应该直接保留吗？

不应该。它可能受相关特征、模型版本、决策集和未来信息风险影响；当前协议还要求确认阶段同种子重训。

## 10. smoke 通过代表模型性能好吗？

不代表。smoke 只证明数据、构建、训练、保存和加载链路基本可运行，不产生性能结论。
